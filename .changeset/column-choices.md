Editors choose which columns the collection list shows. A Columns button opens a menu with a check mark for Slug, Status and every field that can be a column (`text`, `url`, `date`, `datetime`, `number`, `boolean`, `select`, `reference`); the first column always shows, the menu stays open while you tick, and Reset to default goes back. The choice is kept per collection in a cookie, `mnml_cols_<collection>` (set on the admin path for a year, only when an editor changes columns), and the server renders it. Filters follow the chosen columns: a field's filter shows only while its column does (Status with the Status column), and a filter on a hidden column is ignored until the column returns; before a choice every filter shows as configured. New `columnChoices` option on `collection()` limits the menu to the field names you list, or `false` hides the button. `MenuAction` gets an optional `keepOpen` for on/off items. The list now uses the full width of the page (it was capped at the form width, so extra columns overflowed); at narrow widths it scrolls inside its card. Not breaking: without a choice, the table is as before.
